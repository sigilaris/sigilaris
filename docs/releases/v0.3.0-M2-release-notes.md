## Scope

M2 packages the reviewed post-M1 application-safety and exact-pipeline
hardening. It keeps the M1 protocol versions and the one-producer,
one-consumer exact dependency boundary.

- Admission capacity follows the authoritative application journal and
  conservatively accounts for admission rows not yet journaled. Accepted exact
  work owns drain liveness and advances its deadline watermark.
- Canonical expiry and drain readiness are checked in one application-store
  transaction. Terminal execution identities survive reuse of their old input
  rows, preventing reacquisition of an expired execution.
- Journaled terminal exact history survives verifier-profile retirement.
  New and nonterminal work still requires the active profile. Unchanged
  reconciliation does not create journal entries.
- Coherent legacy drain state is repaired only after journal/physical
  equivalence is proven. The safe-direction repair is itself journaled and
  subsequent restarts are idempotent.
- Exact uniqueness indexes retain identifiers and commitments instead of
  complete payloads. Replay reads immutable primary rows under the store gate.
  Ambiguous primary writes invalidate the derived indexes until restart;
  corrupt/conflicting primary rows fail startup with key diagnostics.
- Exact waits use bounded exponential polling with a five-minute hard cap.
  Operator diagnostics require explicit authenticated endpoint mounting.
- Block views, split header persistence, manifest construction, and exact
  descriptor boundaries reject invalid versioned commitments.

## Migration From M1

Upgrade all five module coordinates together and recompile custom integrations:

- Use `ExactPipelineAdmissionService.create` and provide
  `ApplicationSafetyRuntime`.
- Handle manifest `withComputedDigest` and `computeConfigurationDigest`
  results as `Either`; unsafe construction helpers are for trusted fixtures.
- Handle `BlockStore.putHeader` as `EitherT`.
- Preserve `ApplicationSafetyState.terminalExecutions` and expire through
  `expireExecution`.
- Update exhaustive matches for new application-safety, input-validation,
  and manifest-validation failure cases.
- Implement `ExactTxPipelineStore.getByRequestIdentity` in custom stores and
  update derived ownership indexes consistently with primary records.
- Implement `ExactTxPipelineStore.countUnjournaled(journaledPipelineIds, stopAt)`
  as one bounded primary-key scan that counts non-journaled rows up to
  `stopAt`, returning zero for nonpositive limits. Repeated full-record
  decoding or sorting is not an acceptable admission-capacity implementation.
- Explicitly mount `applicationStatusEndpoint` on an authenticated operator
  plane; it is absent from the default exact endpoint bundle.
- Accommodate the five-minute maximum exact wait, including absent timeouts.
- Reconcile under the current manifest and drain before retiring a profile.
  Preserve terminal exact history across rotation.
- Require canonical 32-byte lowercase verifier-manifest digests. A legacy
  noncanonical configured digest requires drain/rotation using the old binary;
  it cannot be silently rewritten without changing configuration identity.

Back up the complete stopped-node consistency group before the first M2
start: application safety/journal, exact admission/idempotency, generic
pipeline, block, consensus, and state namespaces. Recovery may append a
`repairLegacyDrainState` entry. Physical/journal disagreement still refuses
startup. Restoring one namespace independently is unsupported; retain the
pre-upgrade backup for rollback instead of assuming an older binary can read
the upgraded store.

The repair warning is best-effort and can be lost across a crash before
notification. The journal entry is the authoritative record. Exact `list`
ordering is backend-specific, with no cross-page snapshot guarantee during
writes; startup reconciliation is order-independent and precedes admission.

The public [integration guide](v0.3.0-M2-integration-guide.md) describes the
full registration, submission, drain, and recovery workflow.

## Release Review And Lessons

- Review found a missing `countUnjournaled` migration instruction and an
  overstated verifier-slot uniqueness requirement; both guides now match the
  public APIs and pair-based registry validation.
- The first expanded Scala.js consumer exposed missing npm dependencies even
  on a rejected manifest path. Pinning those dependencies and executing both
  linker outputs made the standalone consumer representative of a real
  downstream build. The JVM consumer runs in a fork for correct IOApp cleanup.
- The integration guide lives in `docs/releases` because public snapshot
  export excludes `docs/dev`; published migration instructions must be
  present in the exported tree.
- Remaining code changes are tracked in proposed plan 0032. They do not enter
  the M2 artifact freeze. Subsequent releases should retain explicit npm
  setup, complete abstract-store API migrations, public documentation checks,
  and signed/local/public artifact comparisons.
- Final preparation review: `No finding`. New public-document relative links
  and `git diff --check` passed; the reviewed runtime behavior is unchanged.

## Follow-up Work

The non-blocking fifth-review suggestions are tracked in
[plan 0032](../plans/0032-application-safety-and-exact-pipeline-operational-hardening-plan.md):
observer exception isolation, typed alias-write failures, synchronized index
rebuild, corruption diagnostics, and targeted regression gaps. The plan is
proposed work after M2, not part of this release.

Checkpointed journal retention, a single-namespace exact transaction,
event-driven waits, and explicit V2 cutover wiring remain separate follow-up
work. M2 does not expand the exact protocol to arbitrary DAGs, multiple edges,
cross-pipeline or cross-epoch consumption, or manual lock release.
