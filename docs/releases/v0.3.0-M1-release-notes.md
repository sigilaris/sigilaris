## Release Scope

Sigilaris 0.3.0-M1 introduces an application-neutral, crash-safe substrate for
height-bounded application locks and one explicitly registered exact
`Producer -> Consumer` dependency. It ships the ADR-0035 execution substrate
and the ADR-0036 exact pipeline contract together.

- Application lock, effect, and reservation artifacts bind protocol version,
  application epoch/configuration, validator set, exact input commitments,
  execution plan, and one inclusive `lastInclusionHeight`.
- Locks and reservations can resolve only through canonical application or
  finalized-height `expiredUnapplied`; wall-clock time, best height, and a view
  change do not release live state.
- V2 block headers commit an execution-plan root. Conflict-free waves have
  canonical member order; ordered waves preserve signed order and apply
  atomically.
- Registered `exactV2` profiles support `orderedAtomic` and
  `certifiedAncestor` while keeping application transaction and reference
  codecs outside Sigilaris.
- The application journal is the crash-recovery boundary for locks,
  reservations, applied executions, terminal outcomes, and exact lifecycle
  projection. Startup reconciles configured, registered, journaled, exact
  admission, and physical identities.
- Configuration changes use a finalized-height drain-to-empty state machine.
  A non-empty lock domain cannot rotate or be cleared administratively.
- The existing generic v1 pipeline request, identity, idempotency, projection,
  and historical records retain their previous semantics.

## Compatibility Boundary

M1 activation is atomic. The active manifest must require block header `2`,
execution plan `1`, lock `1`, effect `1`, exact pipeline `2`, and application
journal `1`, and every declared profile must have an exact verifier
slot/manifest-digest registration. Mixing manifests, epochs, or Sigilaris
module versions is unsupported.

Historical v1 block headers and generic v1 pipelines remain readable through
their explicit compatibility paths. A historical application journal delta is
pre-exact only when `exactPipelines` is absent; a present malformed field is
corruption and fails startup. Generic records never gain exact locks or
same-block dependency semantics by inference.

## Known Limitations

M1 intentionally supports one producer, one consumer, one exact dependency
edge, and one common deadline. Arbitrary DAGs, branches, more stages, implicit
`Latest` lookup, cross-pipeline consumption, cross-lane chaining, cross-epoch
locks, and early/manual release require a new protocol version. The operator
surface exposes read-only status; embedders must put drain and activation
methods behind an authenticated, serialized operator plane.
