## Release Scope

Sigilaris 0.2.12 repairs the canonical BigNat byte encoding at the historical
exact-120 boundary and adds an injectable, single-result transaction-pipeline
identity strategy.

- An exact 120-byte magnitude remains `f8 || data(120)`.
- Magnitudes from 121 through 255 bytes now use
  `f9 || u16be(length) || data`; the canonical 121-byte prefix is `f9 00 79`.
- Longer lengths use `max(2, minimalUnsignedWidth(length))` and canonical
  unsigned big-endian length bytes.
- The decoder rejects leading-zero magnitudes, redundant or over-wide length
  forms, truncated input, and non-canonical encodings.
- `TxPipelineIdentityStrategy[F]` calculates the canonical payload hash and
  pipeline id once so admission can reuse a consistent identity result.
- The default v1 strategy preserves the existing SHA-256 preimage and pipeline
  id bytes on JVM and Scala.js.

## Compatibility Boundary

This patch release contains a protocol-visible correction for 121-255-byte
BigNat magnitudes. Values up to 120 bytes and values of at least 256 bytes keep
their existing canonical representation, but affected durable or signed data
must be migrated from authoritative typed values. There is no safe heuristic
for rewriting the ambiguous pre-0.2.12 byte stream.

Because Sigilaris uses `early-semver`, dependency resolution can treat 0.2.12
as compatible with 0.2.11. Consumers must pin every Sigilaris module to one
version and coordinate validator/writer activation; mixed encoder and validator
versions are unsafe for affected values.
