# Initial bootstrap and controlled ordinary signing

This page describes the maintained neutral bootstrap and the production JVM boundaries introduced by plan 0033 Phase 5. Bootstrap starts a new consensus domain from an authenticated source snapshot. It does not reinterpret the source checkpoint as a target-chain block.

## Installed initial parent

`InitialBootstrapConsensus.genesis` derives the actual V2 header G at height 0 from `VerifiedBootstrap`: no parent, canonical empty body and execution plan, the inherited source state root, and the signed bundle timestamp. The initial quorum's proposal subject is the domain-separated `BootstrapSubject` commitment to the bundle digest and G block ID. Its votes use the existing HotStuff `UnsignedVote` signing bytes and existing quorum encoding. G is never represented by a fabricated `Proposal` or `FinalizedAnchorSuggestion`.

`InitialStateInstaller` exclusively owns the same target `DurableJournal` that is subsequently passed to `JournalSafetyStore`. The existing schema-2 operation 8 records `Bound → Installed → Signing → Opened`; operation 12 records the exact initial vote intent. Binding retains and forces the complete original signed bundle, evidence baseline, source inventory and payload, source fence, controller snapshot, and every referenced original artifact before selecting Bound. Installed selects the actual source-state and initial-safety inventories before any vote. A nonvoter can advance directly from Installed to Opened after verifying an actual initial quorum.

The installer is sealed. Its private prepared vote binds an instance lease and the original committed intent. Before initial key use, it reauthenticates the complete source and startup history and exposes a temporary exact request/signer/key/journal-history lease only during the actual controller callback. `InitialBootstrapSigningAuthentication.authorize` requires that actual installer lease. An interpreter uses a deferred reference to the real installer: original controller recovery can precede the installer, while fresh signing cannot.

The private `VerifiedInitialParent` becomes available only after the actual quorum has been authenticated and Opened forced. It retains the original source payload read back from the journal and the actual journal/controller identities. `HotStuffProposalParent` explicitly distinguishes ordinary certified proposals from this initial capability. The initial assembler accepts it only at target height 1, for the exact G parent and bundle-bound QC. It requires `executeInitial` to produce one compatibility opening with a `ConsensusTransaction` source and `None` input-lock certificate. Actual input derivation, empty eligible lock subset, maintenance authority signature, envelope deadline and instrumented execution are checked by the configured public request verifier and `OpeningValidation` before voting.

The ordinary ancestry and transaction-uniqueness traversal may terminate at the explicitly supplied installed G anchor. This does not create a G proposal, historical source-chain block, or three-chain finality. Subsequent parents use their actual retained proposals and QCs. The public branch and exclusion metadata retain the actual tracker's `bestFinalizedBlockId = None` before the first real finality. The transaction-uniqueness cache records `initialStopBlockId` separately from its actual finality key; G is only an authenticated traversal stop.

The neutral embedder explicitly installs `V2BootstrapFixture.ReplayPolicyDigest` (the fixed registered policy identifier 708). Its target transaction language accepts only the authorized `SignedOpening` bound to this fresh full context, G, source checkpoint, payload and signed deadline. Original source snapshot bytes and their authority signature establish imported state; they are not reusable target transaction authorization. The actual transaction verifier checks the selected source's replay-policy binding. The public abandonment case submits those original signed source bytes and a deadline-modified opening and verifies rejection. This is an explicit neutral application policy, not a claim that a validator-domain change automatically changes every application's user-signature rules.

## Auxiliary original evidence and request encodings

The auxiliary encodings below are strict canonical local evidence. They do not change HotStuff proposal, vote, timeout, new-view or quorum signing bytes.

| Product | Canonical fields |
| --- | --- |
| `BootstrapInstallationEvidence` | format 1; original `SignedBootstrapBundle`; `EvidenceBaseline`; encoded source inventory; source-state payload; `SignedFencePromise`; original controller snapshot bytes; ordered original `(EvidenceRef, bytes)` artifacts |
| `InitialBootstrapSigningRequest` | format 1; bundle digest; retained initial vote-intent digest |
| `HotStuffControllerRequest` | format 1; closed kind tag; canonical payload bytes |
| `ControllerConsensusVote` | local voter; actual complete signed `Proposal` |
| `ControllerApplicationVote` | full `DomainContext`; exact canonical application/consensus signing preimage |

The closed controller kind tags are Proposal 1, Vote 2, Timeout 3, NewView 4, and Application 5. Their payloads contain the existing unsigned typed artifact, an actual voter/proposal pair, or full application context/preimage as applicable. Initial bootstrap requests have their own codec and cannot select an ordinary request branch.

Installation and initial-certificate blobs use the `bootstrap-installation` and `bootstrap-certificate` namespaces. Retained content hashes use `sigilaris.application.bootstrap.retained-content.v1`; initial quorum subjects use the core frozen `BootstrapSubject` domain. Installation inventory and every referenced blob are checked again on restart. A different signed bundle cannot replace the selected identity. A complete prepared journal tail is forward-completed only after original authentication. A missing or changed original source, archive, proof or immutable blob prevents Ready.

## Actual key ownership and ordinary runtime

`HotStuffControlledSigning.bootstrap` and `.handover` bind the actual installed capability, target journal, safety store, finalizer, pinned historical profile and key-owning controller. Supported configurations provide no raw local keys. Both explicit emission and the automatic pacemaker use the same closed controller path for proposals, votes, timeout votes and new-view messages. V2 application votes continue through full source/execution verification, exact preparation, durable reservations and before-sign intents.

Current authorization and original signature recovery are separate. `ControllerApplicationSigning.recovery` reauthenticates the original complete forced source/vote evidence before a live safety store exists; it cannot authorize new key use. The outer controller interpreter independently checks every application request's supplied signer/key against the actual validator set selected by its pinned full context. After actual application recovery, `authenticated` additionally requires the same store's and finalizer's temporary leases bound to the exact preimage and complete committed history. The fresh proposal/timeout/new-view path also requires a separately decoded control request under these gates; Vote and Application tags cannot use the control permission API. Source/archive/fence loss, pending materialization, stale publication, expired voting deadlines and failed exact preparation cannot be bypassed with direct `controller.sign`.

The exported `V2SigningAuthorizationConformance` checks these current permissions through the public controller authenticator immediately before the actual neutral key callback. Seven public cases cover a safety-only request without the finalizer permission, another independently valid forced preimage, wrong voter/context, changed committed history, original-only recovery, failure/cancellation cleanup, control request relabelling, and lock/effect/consensus finality reaching D after permission acquisition. Rejection leaves the key-use count at zero and preserves the durable intent; a valid retry uses the key once. The private lease-state tests remain additional implementation checks. The [post-plan review gate](post-plan-review.md) records this added public coverage separately from the original P6 run.

Completed identical controller requests return their original durable signature without using the key again. Incomplete requests must satisfy current authorization before retry. Original recovery does not impose today's active window or live lifecycle on a historically valid signature.

Separate original-source fixtures exercise NoPriorDomain, a present retired archive, wholly absent retired state, and partly absent retired state; deleting the required original retired report is rejected. Partial absence retains both original PresentContent and HistoricalAbsence references for the same retired domain. Independently authenticated present and missing scopes must be disjoint; the public negative uses an actual signed original report with overlapping claims. Duplicate evidence references are rejected by the canonical codec.

Each case checks ordinary automatic descendants, actual three-chain finalization, materialization, empty lock/effect-vote inventories, absence of fabricated height-0 proposals, and same-journal/controller reopen. ## Initial certificate equivalence

Each validator may install a different canonical initial QC, including different valid three-vote subsets or a four-vote quorum. The first block must reference the exact installed bundle/G subject and first-height context, and every supplied vote must authenticate against that bundle's validator set. Local certificate byte equality is not required. Live initial-parent validation, controller proposal authentication and original-history replay follow this rule. The public four-node bootstrap cases now exercise divergent certificates through opening, finality and restart.
