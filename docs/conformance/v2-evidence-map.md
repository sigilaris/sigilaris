# Plan 0033 requirement-to-evidence map

Public case families below live in exported `release-conformance/shared` main sources. The standalone V2 runner executes shared protocol cases on JVM and Scala.js and storage/consensus cases on JVM. Source wrappers call those same case bodies. [P6 gate](p6-gate.md) records the final source, exported consumer and five-coordinate candidate artifact results separately. Candidate staging does not establish public Maven availability. The [post-plan review gate](post-plan-review.md) records later corrections and their new source/artifact identities separately from that original P6 run.

The [full-review correction gate](full-review-corrections-2026-09-12.md) records the later QC-subset, audit-lifetime, observer and tooling corrections and explicitly retained design backlog.

All cases use the [frozen V2 contract](v2-contract.md), [core inventory](core-compatibility-inventory.md) and [runtime inventory](runtime-compatibility-inventory.md). Historical artifact behavior remains pinned to the separately executed [M2 baseline](m2-baseline.md) and [M1/M2 protocol vectors](historical-protocol-vectors.md).

The independent transition oracle recalculates 55 fixed vectors using standalone canonical encoders, Keccak and deterministic ECDSA, then compares JSON and Scala literals without modifying either. It does not import the SDK. Runtime conformance additionally verifies actual signatures, original source files, durable force boundaries and public application execution; a matching digest alone does not establish activation authority.

Unsupported deployment histories remain rejected. In particular, default historical journals without original before-sign consensus safety and issuance coverage cannot be upgraded by reconstructing missing promises. Restore verification reports eligibility and never performs an implicit destructive rollback. Candidate conformance does not complete the separately scoped operations/security hardening work or authorize deployment.
