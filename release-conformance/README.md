# Standalone public protocol conformance

This build resolves all five selected Sigilaris Maven coordinates and compiles the exported consumers without the parent build, source project, Maven Local or Ivy Local. Historical M1/M2 provenance remains separate from the additive V2 contract. The [M2 runtime baseline](../release-smoke/README.md) has its own build.

```sh
./run-conformance.sh 0.3.0-M1 legacy-m1
./run-conformance.sh 0.3.0-M2 legacy-m2
./run-conformance.sh 0.3.0-M3 v2
```

The third argument explicitly selects an HTTPS or absolute file Maven staging repository. Two arguments select public Maven Central only. The script isolates its global sbt configuration and Coursier cache, verifies exactly three JVM and two Scala.js artifact identities from the selected Sigilaris repository, writes SHA-256 manifests under `target/identities`, executes the maintained JVM historical recovery probe against those selected artifacts, and executes JVM, Scala.js fast linking, and fully optimized Node.js. It uses `npm ci --ignore-scripts` with the committed lockfile for the JavaScript runtime dependencies.

In staging mode, every Sigilaris jar must resolve from that exact staging origin; a missing staged coordinate cannot silently fall back to Central and pass. Central remains available for transitive dependencies. HTTPS staging URLs must have a host and no userinfo, query or fragment.

A candidate staging pass is not public Maven publication. The release default `0.3.0-M3` now resolves from Central; there is no local-publication fallback. The [M3 publication record](../docs/conformance/m3-publication-2026-09-14.md) records the public gate separately. The [P6 evidence record](../docs/conformance/p6-gate.md) separates source, candidate artifacts, public export and the later public-Maven gate. The [post-plan review](../docs/conformance/post-plan-review.md) records subsequent corrections and their fresh source/artifact manifests; the original P6 manifests retain their historical meaning. The [M3 crypto security record](../docs/conformance/m3-crypto-security-2026-09-13.md) covers the current runtime updates, the remaining unpatched elliptic Low advisory and the separate build-tool backlog.

## Executed contract

[The shared runner](shared/v2-runner/scala/org/sigilaris/conformance/V2ConformanceMain.scala) executes the same canonical contract on both platforms. [The JVM runner](shared/v2-jvm/scala/org/sigilaris/conformance/V2PlatformConformance.scala) additionally executes real filesystem, controller, exact pipeline and four-validator cases.

- [Historical vectors](shared/legacy/scala/org/sigilaris/conformance/LegacyProtocolVectors.scala) preserve the distinct M1/M2 parser and identity rules under pinned original artifact checksums. Header 2 alone does not identify application V2.
- [Core conformance](shared/v2/scala/org/sigilaris/conformance/V2CoreConformance.scala), [certificate conformance](shared/v2/scala/org/sigilaris/conformance/V2CertificateConformance.scala), and [production opening validation](shared/v2/scala/org/sigilaris/conformance/V2OpeningConformance.scala) exercise independent inputs/lock subsets/footprints, canonical plans, actual signatures, optional certificates, exact authorities and hidden-access rejection.
- [Transition conformance](shared/v2/scala/org/sigilaris/conformance/V2TransitionEvidenceConformance.scala) checks eight schema families and [55 fixed literals](shared/v2/scala/org/sigilaris/conformance/V2TransitionGoldenVectors.scala). The older [16 executed core vectors](fixtures/v2-core-vectors.txt) remain unchanged. Run `python3 tools/verify-transition-vectors.py` to independently recompute the transition bytes, preimages and hashes and compare both [JSON](fixtures/v2-transition-vectors.json) and Scala literals. This Python primitive encoder/Keccak/RFC6979 implementation imports no Sigilaris or crypto package and never regenerates the expected files during verification.
- [Durable voting](shared/v2-jvm/scala/org/sigilaris/conformance/V2VotingConformance.scala), [canonical application recovery](shared/v2-jvm/scala/org/sigilaris/conformance/V2RecoverableApplicationConformance.scala), [canonical ancestry](shared/v2-jvm/scala/org/sigilaris/conformance/V2CanonicalAncestorConformance.scala), and the exact/ordered consumers verify complete reservations, original proof recovery, both exact modes, terminal ownership and a 100,000-identity persisted witness. They run actual IO assertions independently of MUnit.
- [Current signing authorization](shared/v2-jvm/scala/org/sigilaris/conformance/V2SigningAuthorizationConformance.scala) checks seven public permission/failure/deadline cases through actual controller authentication before the neutral key callback. Original evidence validation alone cannot grant fresh key use, and failed/cancelled use retains the intent while clearing permission.
- [File journals](shared/v2-jvm/scala/org/sigilaris/conformance/V2FileJournalConformance.scala), [key-owning controllers](shared/v2-jvm/scala/org/sigilaris/conformance/V2FenceControllerConformance.scala), and [complete consistency groups](shared/v2-jvm/scala/org/sigilaris/conformance/V2ConsistencyGroupConformance.scala) inject durable-write failures, inspect original physical files, reject source loss and verify complete activation/restart/restore eligibility.
- [Initial bootstrap](shared/v2-jvm/scala/org/sigilaris/conformance/V2BootstrapRuntimeConformance.scala) runs four actual nodes for no-prior, retained retired, wholly absent retired and partly absent retired source forms. A fifth case retains an abandoned mandatory opening's actual reservation through restart, rejects an empty-first-block bypass and source-signature replay, then resumes real quorum finality.
- [Historical handover](shared/v2-jvm/scala/org/sigilaris/conformance/V2HistoricalRuntimeFixture.scala), [ordinary gossip](shared/v2-jvm/scala/org/sigilaris/conformance/V2HistoricalTransportFixture.scala), [canonical faults](shared/v2-jvm/scala/org/sigilaris/conformance/V2HistoricalCanonicalFaultFixture.scala), [original issuance](shared/v2-jvm/scala/org/sigilaris/conformance/V2HistoricalIssuanceConformance.scala), and [three drain routes](shared/v2-jvm/scala/org/sigilaris/conformance/V2HistoricalDrainFixture.scala) retain real signed source history, separate canonical F from working P, preserve original deadlines and exercise actual controllers/journals. [Inventory negatives](shared/v2-jvm/scala/org/sigilaris/conformance/V2TransitionInventoryConformance.scala) and [profile negatives](shared/v2-jvm/scala/org/sigilaris/conformance/V2HistoricalProfilesConformance.scala) reject incomplete original authority and relabelled historical ranges.

Core callbacks are deliberate neutral fixtures; their canonical-vector passes alone do not prove an operational deployment. The JVM fixtures add actual original state replay, signatures, files, consensus messages and key-use barriers under their explicitly installed neutral policies. They do not audit an existing production chain or authorize an unmodified M1/M2 deployment to upgrade. See [historical prerequisites](../docs/conformance/v2-historical-activation.md), [original issuance](../docs/conformance/v2-historical-issuance.md), [initialization](../docs/conformance/v2-initial-bootstrap.md) and [activation integration](../docs/conformance/v2-activation-integration.md).

## Source reuse and release evidence

The core source tests reuse `shared/legacy/scala` and `shared/v2/scala`; JVM source tests reuse `shared/v2-jvm/scala`. Thin private test wrappers call the same exported case bodies. The public exporter removes every `src/test` tree, so the standalone runner requires none of those wrappers. Platform runner directories stay out of core test classpaths.

Retain the selected source/fixture identities, complete run log and all five artifact checksums for each gate. For dependency changes also retain generated POMs: source-only overrides do not protect published consumers. After a separately authorized public release, rerun with a fresh cache and only public Maven resolution. Do not label the earlier explicit-staging result as that later release verification.

The JS consumer checks recovery values 283 and 26 once per output: legacy profiles permit historical exceptions, while V2 requires typed `Left` without throwing. The JVM recovery probe is a compiled sbt source and is invoked by every `run-conformance.sh` profile, including pinned M1/M2. The fixture manifests `legacy-sources.sha256` and `v2-core-sources.sha256`, and `legacy-m*-output.txt`, remain archived P1 evidence at `b9fa3f0`; the output text is not the current runner's complete stdout. The [input correction gate](../docs/conformance/public-input-review-corrections-2026-09-12.md) remains archived at `9a8ebf9`; the [M3 crypto gate](../docs/conformance/m3-crypto-security-2026-09-13.md) is archived at `24c02ef`. The [September 14 guard review](../docs/conformance/m3-crypto-review-corrections-2026-09-14.md) is archived at `ea47ed8`. The [M3 release preparation gate](../docs/conformance/m3-release-preparation-2026-09-14.md) retains the current input inventory and final-version staging validation. The [publication gate](../docs/conformance/m3-publication-2026-09-14.md) records the later public-Maven execution.

All profiles verify the actual `elliptic 6.6.1`, its nested `bn.js 4.12.5`, and `js-sha3 0.8.0` resolution and record loaded file hashes. M1/M2 therefore check their immutable historical JARs against the **updated** JS runtime, not their original vulnerable npm selections. V2 also runs [six independent fixed signing vectors and typed input boundaries](shared/v2/scala/org/sigilaris/conformance/CryptoDependencyConformance.scala) on JVM and both JS outputs. The inconsistent-key fixture requires a typed `Left` from `CryptoOps.sign`; JVM private-scalar validation and JS recovered-public-key mismatch can produce that failure at different stages. `python3 tools/verify-crypto-vectors.py` recomputes the literals independently. `jvm/verifyCryptoIdentities` checks the selected provider and, for V2, the patched Armeria/Netty/native TLS versions and writes their JAR hashes. Source builds expose `coreJVM/verifyJvmCrypto`, `nodeCommonJVM/verifyJvmCrypto`, `nodeJvm/verifyJvmCrypto`, `coreJS/verifyJsCrypto` and `nodeCommonJS/verifyJsCrypto`; `Test / test`, `Test / testOnly` and `Test / testQuick` invoke these guards automatically, including when a filter selects no tests. After changing provider coordinates, clean affected modules and re-resolve before testing or packaging.

**The legacy JVM profiles retain `bcprov-jdk15on 1.70`, which matched five advisories in the [September 13 audit](../docs/conformance/m3-crypto-dependency-audit-2026-09-13.json).** Passing these compatibility profiles does not remediate M1/M2's provider or establish applicability of each advisory to a deployment. The M3 provider update does not retroactively change those immutable releases.

Before every profile, `tools/verify-source-inventory.py` checks independently discovered paths and bytes against [the public input inventory](../docs/conformance/public-conformance-inputs.sha256), including platform sources and exporter tooling. sbt then runs `jvm/verifySourceIdentities` and `js/verifySourceIdentities` to check its actual `Compile / sources` against that inventory and write `target/identities/PROFILE-PLATFORM-sources.sha256`. A newly selected source cannot silently escape the recorded input set. Generated/editor directories are excluded from repository input discovery, but selected compiler sources are always checked. Run the Python verifier with `--write` only to deliberately freeze reviewed inputs; execution never updates expected hashes.
